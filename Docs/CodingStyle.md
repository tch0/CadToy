# 项目编码风格

文件与目录管理：
- 模块头文件与源文件放到其下的`inc/ src/`目录中。
- 如果文件很多功能复杂`inc/ src/`下可以分目录（目前只有tchCadToy主项目这样做），需要分别对应。
- 文件不多，不算复杂那就在`inc/ src/`下用由文件命名区分即可（可用不同前缀表示同模块中的不同功能）。
- 文件名同该文件的主要类的类名，如果是综合性的包含多个工具的文件，则给合理的命名，大驼峰。

命名：
- 类名大驼峰，方法变量小驼峰，成员变量加`m_`，静态变量加`s_`前缀。
- 枚举值以`k`开头，类似`kInputTypeString`，整体小驼峰。
- 指针以`p`开头，比如`pDatabase m_pGraphicsDataCache`。

缩进换行大括号：
- 只使用4空格缩进。
- 单行的块一定要加`{}`包起来。
- `{`不换行。
- `else`前的`}`可以选择换行可以不换：
    - 如果需要对`else`块进行注释，`if`中逻辑长那就换行。
    - 如果`if else`块都很短，逻辑简单，那就不用换。
- 函数内的空行保留缩进空格到对齐的位置，而不是只有一个空行。

注释：
- 尽可能加注释，让人通过注释一眼就能看出代码片段功能。
- 虽然好的代码基本都可以充当注释，但不能完全替代且有注释阅读速度是会质的提升的。
- 通常来说只使用单行注释`//`，对特别复杂的全局函数需要说明其各个参数详细功能可以使用多行注释`/** ... **/`。
- 一段段完整功能片段之间需要合理加空行分隔。
- 类的成员函数，一组同类型或者关于某个功能的函数可以放一起，前面加行注释，然后每个函数末尾注释各自详细信息。
- 从资源文件中加载的资源，将中文版本注释在行尾方便查看。

头文件组织：
- 包含头文件，所有标准库、第三方库全部使用`<>`，项目头文件使用`""`。
- 头文件和源文件中的包含头文件需要分组，通过注释说明，各组之间必须流出一行空行。
- 无论该组有没有包含头文件，注释都必须要有。
- 头文件中：`#pragma once`、C++ 标准库、第三方库、项目头文件。
```C++
# pragma once
// C++ 标准库

// 第三方库

// 项目头文件
#include "InputContext.h"
```
- 源文件中：对应头文件、C++ 标准库、第三方库、项目头文件。相比头文件多了一个对应头文件。
```C++
// 对应头文件
#include "Command.h"

// C++ 标准库

// 第三方库

// 项目头文件
#include "InputContext.h"
```
- 最后一个头文件距离文件中第一行具体代码留出两行空行。

命名空间：
- 命名空间内部所有代码都不换行，顶格写，无论多少层。
- 命名空间的`}`后必须注释说明是哪个命名空间的。
- 命名空间嵌套时紧挨着两行一起：
```C++
namespace tch {
namespace {

...

} // anonymous namespace
} // namespace tch
```
- 不在头文件或者源文件`using`任何命名空间，标准库类型函数必须加上`std::`，任何时候都不能`using namespace std;`。
- 命名空间内引用其他嵌套命名空间代码也是，比如`tch`命名空间内引用`tch::DbJsonUtils`内的东西就加`DbJsonUtils`。
- 只有一个例外，`main.cpp`中使用了`using namespace tch;`。代码很少不用担心。
